## 1. 项目范围与用户

### 1.1 角色与场景

**目标用户**：产业链专班 / 园区管委会规划人员。根据产业链短板和配套缺口，围绕缺口环节挑选候选企业，逐户生成招商方案，匹配对应政策包，形成行动计划后提交审核。

三视图职责边界：

| 角色视图 | 使用者 | 关注点 | 共享模块 |
| --- | --- | --- | --- |
| 决策领导看板 | 分管领导、招商局长 | 产业链全貌、短板与补链方向、重大项目研判 | D1 短板识别 |
| 招商专员看板 | 一线招商人员 | 锁定目标企业、查看评分与风险 | D4 评分引擎 |
| **规划人员看板（本文档）** | **专班规划人员** | **补链缺口 → 候选企业 → 方案生成 → 政策匹配 → 核验留痕** | **D5 方案生成 ＋ LLM ＋ 政策匹配** |

典型场景：

- **场景 D（主）**：规划人员从短板任务出发，查看候选企业的画像、评分与风险，选定企业触发生成方案；系统汇总数据库中的画像、评分、短板结论与政策候选，由 LLM 组织语言生成推介要点、政策包、谈判策略与行动计划，人工核验后定稿归档。
- **场景 D1**：按短板环节跟踪候选覆盖与方案状态，识别尚未形成方案的缺口。
- **场景 D2**：核对方案匹配的政策条目、匹配理由与来源。
- **场景 D3**：对 AI 生成内容逐条核对数据来源，采纳定稿或驳回，保留版本与核验记录。

### 1.2 项目边界

**本期范围内**：短板任务与候选企业展示；方案生成（推介要点＋政策包＋建议方案）；政策匹配；方案状态流转与人工核验；版本留痕与 Markdown 导出。

**本期范围外**：方案在线协同编辑与多级审批；Word/PDF 模板导出；政策库维护界面；移动端、多区域部署、生产级权限；模型训练微调。

## 2. 核心业务流程

主流程：

```
选择补链任务（D1）
  → 浏览候选企业清单（D2+D3+D4 聚合），查看画像摘要、评分、风险
  → 选定企业，前置校验（画像 / 评分 / 政策候选齐备）
  → 服务端装配上下文（仅取数据库字段）
  → 政策匹配（规则召回 ＋ 可选语义检索）
  → LLM 结构化生成；失败 / 超时 / 结构非法 → 规则模板兜底
  → 方案草稿入台账，记录生成方式、版本、上下文快照与留痕
  → 规划人员人工核验：采纳定稿 / 驳回（意见必填）
  → 重新生成产生新版本，旧版本归档只读；可导出 Markdown
```

状态流转：`待生成 → 草稿 → 待审核 → 已定稿`；`待审核 → 草稿`（驳回）；已定稿重新生成另存新版本；生成失败回到待生成并记录原因。

### REQ-PLAN-04 招商方案生成（LLM）

| 项 | 内容 |
| --- | --- |
| 用户 / 场景 | 专班规划人员；场景 D，生成一企一策方案 |
| 输入 / 前置 | 企业画像、关联短板、政策候选已取得；评分可缺失（D4 接口到位前临时放行）；LLM API 可用（或允许兜底） |
| 处理规则 | 组装上下文（仅数据库字段）→ 按提示词模板调用 LLM → 输出结构化方案（推介要点、政策引用、谈判策略、行动计划）→ 结构校验；政策 ID 必须来自候选集 |
| 输出 | 方案草稿（状态：草稿），含正文、生成方式、模型版本、生成时间 |
| 异常处理 | LLM 失败/超时/超限自动降级规则模板并标注"模板兜底"；输出结构非法重试一次，仍失败保留上下文并提示人工撰写；画像或短板缺失阻止生成；评分缺失在 D4 到位前可先按画像生成并标注"评分待补"，D4 到位后恢复评分前置校验 |
| 优先级 / 验收 | 高；文本含推介要点、匹配政策、建议方案三部分；企业数据全部取自数据库；失败有兜底与提示 |
| 设计位置 / 测试 | `PlanSectionView.vue`、`plan_service.py`；TC-08、TC-09、TC-10、TC-11 |

## 4. 非功能需求

| 编号 | 类别 | 指标 / 要求 | 验证方法 |
| --- | --- | --- | --- |
| NFR-01 | 性能 | 看板首屏加载 ≤3 s（本地演示环境）；LLM 调用超时阈值 30 s，超时走兜底；生成过程有明确 loading | 本地演示计时；模拟超时观察降级 |
| NFR-02 | 一致性 | 看板展示的画像、评分、短板结论与上游接口一致，不二次加工改写 | 同一企业跨看板核对字段 |
| NFR-03 | 可解释 / 可溯源 | 方案中每条企业数据、每条政策均标注来源；LLM 仅组织语言，不产生库外事实 | 抽查条目能否回溯数据库字段 / 政策记录 |
| NFR-04 | 可用性 | 复用共享前端框架的导航、组件与路由；三视图同一组件库；原型离线可打开 | 原型双击可操作；组件划分与 Vue3 框架对应 |
| NFR-05 | 健壮性 | 单模块接口失败不导致整页崩溃；LLM 不可用时模板兜底仍可生成方案 | 断网 / 关闭 LLM Key 场景走查主流程 |
| NFR-06 | 数据安全 | 不记录、不展示 API Key；演示数据脱敏；定稿前 AI 内容标识清晰 | 检查日志与页面文本 |
| NFR-07 | 兼容性 | 支持 Chrome / Edge 最新两个大版本；前端按 Vue3 ＋ Element Plus 组织 | 浏览器走查 |

## 5. 外部接口与数据约束

| 接口来源 | 提供方 | 取用数据 | 失败处理 |
| --- | --- | --- | --- |
| D1 短板识别（未交付） | 短板识别岗 | 短板环节、缺口类型、优先级、识别依据 | 交付前由 C1 统计临时派生；占位提示，候选清单可独立浏览 |
| D2 企业筛选（已落地 v1.0） | 数据岗 | 候选企业列表、组合条件、命中原因 | 提示筛选服务暂不可用 |
| D3 企业画像（已落地 v1.0） | 数据岗 | 6 维画像字段及 provenance 来源标注 | 缺项显示"—"，方案生成不得编造 |
| D4 适配评分（未交付） | 评分引擎岗 | 总分、维度分、评分理由、风险提示 | 接口到位前分数缺失不阻断生成、标注"评分待补"；到位后分数缺失禁止触发生成 |
| 政策库（已落地 v1.0） | 数据岗 | 政策条目、类型、条款原文、来源链接、匹配理由 | 无命中如实标注，不虚构政策 |
| LLM API | 外部大模型服务 | 结构化方案文本 | 规则模板兜底；结果缓存；调用上限告警 |

**数据约束**：

- 方案引用的企业事实必须来自数据库字段；LLM 仅做语言组织与段落编排。
- 政策引用必须挂接政策库记录 ID，不允许出现库外政策名称。
- 上游画像、评分、短板、政策为只读引用；本岗位不写入业务库。
- 定稿方案引用生成时刻的上下文快照，上游后续数据变更不回溯改写已定稿方案。

- 大模型只负责组织方案文本（推介要点、谈判策略、行动计划），企业事实和政策条款取自数据库；提示词模板留版本号，输出先过结构校验。
- AI 生成内容先存草稿，规划人员核对来源后再定稿；LLM 不可用时走规则模板，结果同样标注并核验。
- 核验责任人：方案生成岗 / 专班规划人员；代码和模型输出都经过本地运行、字段对照后才采用。
