## 1. 用户角色与使用场景

### 1.1 本看板的目标用户

**产业链专班 / 园区管委会规划人员**：根据产业链短板和配套缺口，围绕缺口环节挑选候选企业，逐户生成招商方案，匹配对应政策包，形成行动计划后提交审核。

与另外两个角色视图的边界划分：

| 角色视图 | 主要使用者 | 核心关注点 | 对应共享模块 | 本看板是否涉及 |
| --- | --- | --- | --- | --- |
| 决策领导看板 | 分管领导、招商局局长 | 产业链全貌、短板与补链方向、重大项目研判 | D1 短板识别 | 仅引用短板结论，不做诊断分析 |
| 招商专员看板 | 一线招商人员、项目经理 | 锁定目标企业、查看评分与风险、准备对接材料 | D4 评分引擎 | 仅引用评分结果，不做打分 |
| **规划人员（专班）看板** | **专班规划人员** | **围绕补链缺口组织候选企业、生成招商方案、匹配政策包、审核留痕** | **D5 方案生成 ＋ LLM ＋ 政策匹配** | **本看板** |

### 1.2 典型业务场景

- **场景 D · 招商方案生成（主场景）**：规划人员从短板任务出发，查看该缺口下的候选企业及其画像、评分与风险，选定企业后触发生成招商方案；系统汇总数据库中的画像、评分、短板结论与政策候选，由 LLM 组织语言生成"推介要点 ＋ 匹配政策 ＋ 谈判策略 ＋ 分步行动计划"，规划人员人工核验后定稿归档。
- **场景 D1 · 补链任务跟踪**：按短板环节查看候选企业覆盖情况、各企业方案状态（待生成 / 草稿 / 待审核 / 已定稿），识别尚未形成方案的缺口。
- **场景 D2 · 政策包核对**：查看每份方案匹配到的政策条目、匹配理由与政策来源，核对政策与企业条件是否对应。
- **场景 D3 · 方案复核与留痕**：对 AI 生成的方案逐条核对数据来源，采纳定稿或驳回修改；保留生成版本、模型版本与人工核验记录，便于答辩与追溯。

### 1.3 项目边界

**本学期必须完成（In Scope）**

1. 展示短板任务及其候选企业清单（数据来自 D1/D2/D3/D4 既有接口）。
2. 基于企业画像、评分、短板结论与政策库，生成结构化招商方案文本。
3. 政策匹配：输出匹配政策条目、匹配维度、匹配理由与来源。
4. 方案状态流转与人工核验（草稿 → 待审核 → 已定稿 / 驳回）。
5. 方案版本留痕与基础导出（Markdown / 打印）。

**列入后续迭代（Out of Scope，本期不做）**

- 方案在线协同编辑、多级审批流；
- Word/PDF 模板化导出、政策库维护界面；
- 移动端、多区域部署、生产级权限体系；
- LLM 模型训练与微调；本期不接入付费外部大模型，方案生成以规则模板兜底为主，外部大模型 API 为可替换增强。

| 编号 | 类别 | 指标 / 要求 | 验证方法 |

## 3. 外部接口与数据约束

| 接口来源 | 提供方 | 本看板取用数据 | 失败 / 不可用时处理 |
| --- | --- | --- | --- |
| D1 短板识别接口（未交付） | 短板识别岗 | 短板环节、缺口类型、缺口描述、优先级、识别依据 | 交付前由 C1 环节统计临时派生任务；占位提示，候选清单可独立浏览 |
| D2 企业筛选接口（已落地 v1.0） | 数据岗 | 候选企业列表、组合条件、命中原因 | 提示筛选服务暂不可用 |
| D3 企业画像接口（已落地 v1.0） | 数据岗 | 6 维画像字段及 provenance 来源标注 | 缺项显示"—"，方案生成时不得编造 |
| D4 适配评分接口（未交付） | 评分引擎岗 | 总分、维度分、评分理由、风险提示 | 接口到位前分数缺失不阻断生成，方案标注"评分待补"；D4 到位后恢复：分数缺失禁止触发方案生成并提示先完成评分 |
| 政策库检索（已落地 v1.0） | 数据岗 | 政策条目、类型、条款原文、来源链接、匹配理由 | 无命中或检索失败时如实标注，不虚构政策 |
| LLM API | 外部大模型服务 | 结构化方案文本 | 规则模板兜底；结果缓存；调用上限告警 |

**数据约束**

- 方案正文引用的所有企业事实（名称、规模、技术、投资动向等）必须来自数据库字段；LLM 输出仅做语言组织与段落编排。
- 政策引用必须挂接政策库记录 ID，不允许在正文中出现库外政策名称。
- 演示数据集 ≥50 家样例企业与政策库由数据岗维护，本岗位只读取、不写入业务库。

## 4. AI 使用与人工核验安排

| 环节 | AI 用途 | 人工核验要求 | 责任人 |
| --- | --- | --- | --- |
| 方案生成 | LLM 依据数据库上下文组织推介要点、谈判策略与行动计划 | 规划人员逐条核对数据与政策来源；与库外事实不符即驳回；定稿前双人交叉复核 | 方案生成岗 / 专班规划人员 |
| 提示词模板 | 模板版本化管理，约束模型只使用给定字段、按 JSON 结构输出 | 每次模板变更登记版本；校验输出结构 | 方案生成岗 |
| 兜底生成 | LLM 不可用时规则模板拼接方案 | 兜底方案标注"模板生成"，同样需人工核验 | 方案生成岗 |

> 风险对应：R1（LLM 不可用 / 超限 / 超预算）走模板兜底和结果缓存；R6（LLM 生成内容失实）要求数据只取数据库，模型只组织语言，结果经人工核验后再定稿。
