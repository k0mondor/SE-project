## 2. 本岗自建接口（方案台账 / D5，草案 + 骨架）

前缀 `/api/v1`。上游只读数据在本层聚合后供看板使用；方案写入本服务。

| 编号 | 方法 | 路径 | 说明 | 对应需求 |
| --- | --- | --- | --- | --- |
| P-01 | GET | `/api/v1/planning/shortboards` | 补链任务列表（D1 未交付时由 C1 派生） | REQ-PLAN-01 |
| P-02 | GET | `/api/v1/planning/candidates?shortboard_id=` | 候选企业清单（B1 聚合 B2 画像，评分位留空） | REQ-PLAN-02、03 |
| P-03 | GET | `/api/v1/enterprises/{enterprise_id}/profile` | 透传 B2 画像 | REQ-PLAN-03 |
| P-04 | GET | `/api/v1/enterprises/{enterprise_id}/score` | D4 评分占位，`fit_score=null` | REQ-PLAN-03 |
| P-05 | GET | `/api/v1/policies/match?enterprise_id=&limit=` | 透传 C2 政策匹配 | REQ-PLAN-05 |
| P-06 | POST | `/api/v1/plans/generate` | 触发生成（LLM ＋ 政策匹配 ＋ 模板兜底） | REQ-PLAN-04、05、10 |
| P-07 | GET | `/api/v1/plans?shortboard_id=&status=` | 方案台账列表 | REQ-PLAN-06 |

### 2.1 生成方案 P-06

请求体：

```json
{
  "enterprise_id": 3,
  "shortboard_id": "SB-半导体设备",
  "template_id": "TPL-ONE-COMPANY-v1",
  "mode": "auto",
  "policy_limit": 5
}
```

`mode`：`auto`（先 LLM，失败走兜底）/ `llm`（仅 LLM，失败报错）/ `template`（直接模板兜底）。

处理规则：

1. 装配上下文：B2 画像 ＋ 政策候选集；D4 评分到位后纳入评分与理由快照。
2. 调提示词模板（版本留痕）；LLM 返回结构化 JSON，经 schema 校验，非法结构降级模板。
3. 政策引用二次校验：只保留 C2 候选集内政策 `id`。
4. 方案写入草稿，记录生成方式、模型 / 模板版本、降级原因与上下文快照。

响应 `data`（`PlanDetail`）：

### 2.2 状态流转 P-09

`PUT /api/v1/plans/{plan_id}/status`

```json
{ "action": "submit" }
```

`action`：`submit`（草稿 → 待审核）、`finalize`（待审核 → 已定稿）、`reject`（待审核 → 草稿，必须带 `comment`）。

非法跳转 → `code=40902`，原状态不变；驳回意见为空 → `code=40011`。

### 2.3 错误码

| code | 含义 | 前端处理 |
| --- | --- | --- |
| 40010 | 前置数据缺失（画像 / 短板） | 提示缺项，禁止生成 |
| 40011 | 驳回意见必填 | 阻止提交驳回 |
| 40401 | 暂无评分记录（D4 到位后启用） | 禁止生成，先完成适配评分 |
| 40404 | 方案不存在 | 提示并刷新台账 |
| 40902 | 状态非法跳转 | 原状态不变 |
| 50200 | 上游数据服务不可用 | 占位提示，不阻断本地台账 |
| 50110 | LLM 失败且兜底不可用 | 保留上下文，提示人工撰写 |
| 50111 | 政策库检索失败 | 方案可生成，政策区标注"政策暂不可用" |

## 4. 数据实体（本服务落库部分）

| 实体 | 关键字段 | 说明 |
| --- | --- | --- |
| `plan` | plan_id、enterprise_id、shortboard_id、status、current_version_no、generator、model_version、template_id、created_at、updated_at | 方案主表 |
| `plan_version` | id、plan_id、version_no、generator、model_version、context_ref(JSON)、plan_body(JSON)、trace(JSON)、created_at、archived | 版本与留痕 |
| `policy_match` | id、plan_id、policy_id、match_dimension、match_reason、source | 方案—政策匹配记录 |
| `plan_review` | id、plan_id、version_no、reviewer、reviewed_at、action、comment | 核验流转记录 |

只读引用（不写入）：企业画像（D3 / B2）、评分（D4）、短板（D1）、政策库（C2）。

## 5. 非功能与约束

- **超时与降级**：LLM 调用超时 30 s；失败按 `mode` 策略降级；兜底模板结果同样进入核验流程。
- **快照一致性**：方案引用的画像、政策采用生成时刻快照（`context_ref`）；上游后续更新不回溯改写已定稿方案。
- **可追溯**：画像维度带 `provenance`；政策条目带 `source_url`；方案留痕记录模型 / 模板版本、降级原因。
- **配额**：记录每次调用 token 用量；接近预算阈值时告警并提示切换模板模式。
- **安全**：接口不返回 API Key；日志脱敏；演示数据去除真实联系方式。
