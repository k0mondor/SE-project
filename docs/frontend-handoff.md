# 前端协作交接

当前已完成共享前端、总览页与招商专员看板，并新增 D4 评分服务。决策领导、规划专班仍为独立占位入口，供对应负责人开发。启动后端后，招商专员看板使用真实企业库进行检索、排序与详情展示。

## 页面归属

| 页面 | 开发目录 | 业务职责 |
| --- | --- | --- |
| 决策领导 | `frontend/src/pages/leadership/` | D1：产业短板识别、薄弱环节与补链方向 |
| 招商专员 | `frontend/src/pages/specialist/` | D4：候选企业比较、落地适配与产业契合评分 |
| 规划专班 | `frontend/src/pages/planning/` | D5：政策匹配、招商方案生成与查看 |

招商专员看板由本次框架负责人继续开发；其他页面交由对应同学开发。D2 企业筛选、D3 企业画像及数据采集清洗由数据岗提供，具体接口以仓库的数据岗接口契约及后端实际实现为准。看板负责人负责自己的页面及所需业务逻辑，不能把首页流程展示当成已完成的业务功能。

## 开始开发

1. 按 `frontend/README.md` 安装依赖、启动前后端。
2. 在自己目录的 `index.vue` 替换占位组件。页面私有组件放在同目录的 `components/`，需要时再创建，不预建空文件。
3. 共享按钮使用 `UiButton`，颜色字号引用 `styles/tokens.css`；详细用法见 `frontend-design-system.md`。首页动效只属于总览，不直接套用到业务表格和表单。
4. HTTP 请求经 `api/client.ts`；业务专属接口可新增 `api/leadership.ts`、`api/specialist.ts` 或 `api/planning.ts`。先确认接口、字段及错误返回，再接入页面，不自行假设后端能力。
5. 补齐加载、空数据、失败重试状态；示例数据必须明确标识，不能冒充真实评分或生成结果。
6. 提交前运行 `npm run build` 和 `npm test`，检查自己的路由刷新、返回导航与窄屏显示。公共组件改动需同时检查总览与其他入口。

## 公共边界

`App.vue`、导航、页脚、路由、tokens、共享组件及请求封装由框架统一维护。页面内使用 scoped 样式，不修改全局 body 滚动或覆盖另一页面的样式。可复用组件确认多个页面确实需要后再提升至共享目录。

总览动效默认开启，无开关；页面连续滚动，无吸附卡点；企业 Logo 悬停不停。图标与企业 Logo 来源在各资源目录的 SOURCES 文档中记录。

## PR 拆分

- 第一份：前端框架、总览、设计变量、共享组件、请求封装、三个独立占位入口和交接文档。验证范围为框架与已有接口封装，不宣称三个业务看板完成。
- 第二份：招商专员看板、D4 对接或实现及对应验证；以第一份框架为基础，避免重复混入公共框架文件。
- 其余同学各自在框架合入后的主分支创建业务分支，按页面提交 PR。若框架尚未合入，需明确分支依赖，避免把整套框架重复带入业务 PR。

分支 `feature/specialist-scoring` 基于前端框架提交 `34cfb8d` 开发。评审本次业务变更时，以框架分支为比较基准；框架合入主分支后再调整业务 PR 的目标分支。

## 招商专员看板实现范围

`pages/specialist/index.vue` 已接入搜索、环节筛选、评分排序、规则说明；`SpecialistDetail.vue` 接入企业画像与条形评分图。全部环节会请求各环节的全量结果，统一排序；当前数据每环节不足100家，扩展数据量时需要改为后端全局排名与分页。评分详见 `scoring-engine.md`。缺失评分展示待补充及上下界；暂无主营简介字段，因此卡片暂用环节说明，Logo缺失使用企业名称。

专员页首屏白底，40%–65%屏幕滚动区间内用 GSAP ScrollTrigger scrub 快速变黑；搜索框正常离开屏幕。卡片入场上浮、悬停上移8px，悬停蓝条从10%展开至100%（0.45秒）、离开收回；箭头保持原形，按钮随卡片悬停变蓝；规则按钮沿用共享逐字翻转。离页清理监听、请求、观察器与动效。

环节选择在搜索框下方常驻横向小导航，使用按钮 aria-pressed 标记选中项，蓝字与短下划线强调；不再使用展开面板。选择后点击检索箭头或回车查询；使用标准放大镜。整个专员页面统一变色，详情固定黑底。
