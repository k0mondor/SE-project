## 2. 核心交互流程

### 2.1 主流程：从短板任务到定稿方案

```
选择补链任务（D1）
   │
   ├─ 浏览候选企业清单（D2+D3+D4 聚合）
   │     ├─ 查看画像 6 维摘要
   │     ├─ 查看适配总分 / 维度分 / 风险提示
   │     └─ 选中目标企业
   │
   ├─ 点击「生成招商方案」
   │     ├─ 校验：画像、评分、政策候选是否齐备（缺项阻止生成并提示）
   │     ├─ 服务端组装上下文（仅取数据库字段）
   │     ├─ LLM 生成结构化方案 ── 成功 ──→ 写入方案草稿（记录模型版本 / 时间）
   │     │                    └─ 失败 / 超时 / 结构非法 ──→ 规则模板兜底（标注"模板兜底"）
   │     └─ 政策匹配（规则 + 检索）挂接政策条目
   │
   ├─ 规划人员核验方案正文
   │     ├─ 数据 / 政策逐条核对来源
   │     ├─ 采纳定稿 → 状态「已定稿」（记录核验人、时间）
   │     └─ 驳回 → 状态退回「草稿」（驳回意见必填，进入版本记录）
   │
   └─ 方案台账跟踪状态；需要时重新生成（产生新版本）或导出
```

### 2.2 关键交互规则

1. **生成前置校验**：企业画像缺失、评分缺失时，「生成方案」按钮禁用并提示缺哪项数据；评分服务未返回结果不允许进入生成。
2. **生成中状态**：按钮进入 loading，展示"正在汇总画像 / 评分 / 政策并生成方案"；30 s 超时自动降级兜底。
3. **只读区分**：画像、评分、短板结论为只读引用；本看板仅可编辑方案文本的核验结论与意见，不回写业务库。
4. **定稿保护**：已定稿方案不允许直接覆盖；重新生成另存新版本，旧版本只读留存。
5. **AI 标识**：草稿阶段正文旁标注"AI 生成，待人工核验"；兜底方案标注"模板生成"；定稿后标注核验人与核验时间。

## 3. 方案状态流转

| 当前状态 | 允许操作 | 目标状态 | 触发条件 / 约束 |
| --- | --- | --- | --- |
| 待生成 | 触发生成 | 草稿 | 前置数据齐备；LLM 或兜底模板产出结构化方案 |
| 草稿 | 提交审核 | 待审核 | 方案正文非空；至少匹配 0 条政策（无命中需注明） |
| 草稿 | 重新生成 | 草稿（新版本） | 保留旧版本；记录生成方式 |
| 待审核 | 采纳定稿 | 已定稿 | 核验人确认数据与政策来源无误 |
| 待审核 | 驳回 | 草稿 | 驳回意见必填；记录驳回原因 |
| 已定稿 | 重新生成 | 草稿（新版本） | 旧版本归档只读；新版本从草稿重新走核验流程 |
| 任意状态 | 生成失败 | 待生成（保留失败记录） | LLM 与兜底均失败；提示人工撰写并记录原因 |

状态枚举：`pending`（待生成）、`draft`（草稿）、`in_review`（待审核）、`finalized`（已定稿）、`failed`（生成失败）。

## 6. 视觉与可用性约定

- 政务风配色：主色深蓝，辅助色用于状态徽标（高优先级红、中优先级橙、低优先级灰；方案状态蓝 / 绿 / 灰）。
- 所有数据卡片标注来源模块（D1 / D2 / D3 / D4 / 政策库），答辩时能说清数据来自哪里。
- 表格在小屏幕下横向滚动；详情抽屉宽度固定，内容超长滚动。
- 空状态、错误状态、生成中状态均有明确文案，不出现空白页面。
